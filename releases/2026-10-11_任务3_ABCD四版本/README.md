## 起点与控制

四版统一从 BC 倒车车库内开始，车头朝外，车身位置按成功测试摆放，探头八路全亮 `FF`，IMU 数据稳定；电机和逻辑电源共地。上电／复位停机。短按并松开板载 PA15 KEY，或发送单字节 ASCII `G` 启动。运行中按 KEY 或发送 `X` 停止。

A／B／D 出库固定八步：`F100 → R050 → F180 → R060 → F200 → F190 → B037 → R068`，F/B 为 mm，R 为角度。末次 R068 是相对旋转 68°，不是地图绝对角度。出库后接灰度主轨道，普通转弯靠灰度重新收线，不强制每个弯转满 IMU 90°。

A／B 使用 C 后的多图样接管：左右连续 1～3 灯可启动；偏在一侧时限时低速纠线，最多 800 ms、300 左前计数、15°，短暂全灭容忍 120 ms。纠线仅用于已经通过 C 的接管，不插入 D／A／B 普通转弯。之后使用成功正方形基础指令 220、误差乘 22、限幅 100，以及原进弯／转弯／恢复动作。到 C 无须此接管。D 保留实测时的较窄接管条件（中心灯或 60/06）和普通 170／80 参数，不能把它说成新版多图样已经实测。

八路全黑、分散多灯等不确定图样不会被无条件当作偏线。库内起步 FF 定位与 C 后稀疏线接管是两个不同条件，不可混用。

## 编译

下载整个仓库，保留根目录 Core、Drivers、链接脚本及本目录 `build_version.mk`。仅下载某个 main.c 或子目录不能独立重编。

在各版本的 `工程` 目录执行 GNU make：

```powershell
make all
```

工具链位置不同时：

```powershell
make "TOOL_ROOT=C:/你的工具链/tools/bin" all
```

生成 ELF／BIN 在对应 `工程/build` 目录；发布用原样固件在 `固件` 目录。A／C／D 必须与 `SHA256SUMS.txt` 及原样固件比对一致，B 无实车日志。

本目录构建脚本不会烧录、打开串口或启动车辆。执行离线发布检查：

```powershell
python -m unittest discover -s 验证 -p "test_*.py" -v
```

到 B 在 A 检出点重新建立 AB 里程原点，B 窗口暂继承成功 A 点起步正方形的 `5100±900` 左前计数。这与新的 A START 原点不一定完全等效，必须实车标定。不要根据离线通过就认为它已经到 B 成功。
