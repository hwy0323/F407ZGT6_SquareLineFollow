# 发挥一（第四题）：六分支视觉选库

2026-10-17。按本次题目截图更新：颜色只选停车类型，形状只选目标边，不能根据 BC／CD／DA 的先后顺序猜类型。

本工程已通过主机测试和 ARM 编译，生成独立 BIN／ELF；**本轮没有连接探针、没有读取串口、没有烧录或启动车辆**。原三个固定车位工程、第三题以及板上程序均未被这次修改覆盖。

## 六种分支

| 卡片 | 目标边 | 停车类型 | 从 A 通过真弯数 | 动作依据 |
| --- | --- | --- | --- | --- |
| 红圆 | BC | 倒车入库 | 1 | 本轮固定 BC 倒库已现场通过 |
| 黄圆 | BC | 侧方停车 | 1 | 侧停动作旋转复用，尚需 BC 实车验证 |
| 红三角 | CD | 倒车入库 | 2 | 倒库动作旋转复用，尚需 CD 实车验证 |
| 黄三角 | CD | 侧方停车 | 2 | 本轮固定 CD 侧停已现场通过 |
| 红方 | DA／AD | 倒车入库 | 3 | 固定 DA 版由用户确认另一个 Codex 已实测，本仓库未取得该次原始日志 |
| 黄方 | DA／AD | 侧方停车 | 3 | 最新双层 2-2 的侧停动作 |

“动作依据”不是本新视觉固件的整车验收结果。六种识别联动、黄圆 BC 侧停和红三角 CD 倒库仍需实车分别验证。

形状与位置固定：圆形→BC，三角形→CD，正方形→DA。类型不固定：三个车位各自都可以是倒库或侧停，因此支持 RRR、RRS、RSR、RSS、SRR、SRS、SSR、SSS 共 8 种类型排列。R 为倒库，S 为侧停，按 BC／CD／DA 排列。

## 运行流程

1. 在 A 点沿 AB 朝 B 放车，中间循迹对线，摆好唯一一张任务卡。原用户已确认 A 点可以看见卡片，不加识别前的直行。
2. 上电保持停车。KEY 短按松开，或 DAP 发送完整 `@TASK4:VISION:RUN` 加真正换行，才启动本轮。G／T 或其他车位的启动帧不启动。
3. 上轴 PA2 设 150°、下轴 PA3 设 75°，等待至少 1 秒后请求 K230 任务 4。两轴分别按 180°／270°换算；没有角度反馈，等待不等于实测到位。
4. 校验 MV/1 的 SID、SEQ、任务、XOR、颜色／形状／动作一致性。RED 必须 REVERSE，YELLOW 必须 SIDE。不认识、FAIL、超时或链路错误都不出发，不默认某车位。
5. 保存并 ACK 合法结果，生成并锁定一个计划。A 点对线、IMU 新鲜、KEY 松开连续满足 200 ms 后才行车。
6. 始终按 A→B→C→D 顺时针循迹。通过 1／2／3 个真弯后，分别在 BC／CD／DA 搜索所选车位的第一条库线。
7. 停车，执行视觉所选的倒库或侧停动作，完成后保持停机，不出库、不绕回 A。

每次复位只允许一次运动。KEY／DAP 字节 X 停止；上电按住 KEY 再松开不会开车。任务期间视觉断线、会话变化、串口错误、灰度／IMU 过期、里程或动作超限均停车，不自动恢复。

## 非目标车位不再假定类型

经过非目标边时，程序只确认并越过两条库线，不判断那是倒库还是侧停，更不会按“第一个倒库、第二个侧停、第三个倒库”选择动作。

- 非目标边每条库线沿用短停 100 ms、低速带纠线通过；宽度变化不会增加真弯数。
- 每一条已经过的车库边分别保存库线数量，必须恰好为 2；不是只检查全程总数。多一条、漏一条或库线被误当真弯都不能继续入库。
- 仍保留成功正方形控制的 B／C／D 真弯窗口 5100／11299／17567，各 ±900 左前累计计数。普通中间三盏亮不单独判库线。
- 只有视觉选定边、正确真弯数、正确前序库线序列、目标第一条线窗口和连续三次特征确认同时满足，才进入入库。
- 第一条目标库线漏过后停车，不把第二条当作第一条再执行。

这里没有用灰度反推未知车位的类型：任务卡决定目标类型，灰度只负责线。题目默认卡片与实际车位匹配；若人为摆错车位类型，单个库线特征不能保证发现这种错误。

## 车位尺寸变化与标定参数

旧记录的车库类型为 R／S／R，但它们两条库线的中点分别为 8427／14404／20527 左前累计计数。本版只保留这三个中点作为固定场地标定，不保留旧类型顺序作为运行规则。

目标第一条线的位置按“该边中点－所选类型沿边长度的一半”计算，再叠加该分支独立偏移，窗口半宽保留 500 计数。侧停车位较长时，第一条线应更早出现，不能继续共用同一个旧起点。

参数集中在 [task4_config.h](task4_config.h)：

- 三个车位中点、第一条线窗口、5.73 计数/mm 换算。
- 当前记录推得的沿轨道长度：倒库约 300 mm、侧停约 400 mm。它们是沿边方向，不是库深；题目外形为 35×30 cm 与 40×20 cm，若胶带将 35 cm 放在沿边方向，改倒库沿边参数为 350 mm 后重新编译并实测。
- 六个分支各自的第一条线偏移和每一步动作修正。只改某组合时，不连带改变其他五组。

记录计数包含差速转弯，不是纯几何距离。中点、探头安装、负载和整场比例改变仍需重新采集标定，不能承诺任意尺寸地图都能套用。

## 入库动作

采用本轮固定 BC／CD 版本中已实际运行过的连续控制器，没有换回 10.12 的旧侧停参数。

- 倒库：F1198→L9000→B1146，约前进 20.9 cm→左转 90°→后退 20 cm。
- 侧停：L546→F2194→L4193→B1347→R4474；B1347 已包括双层版额外倒车 3.5 cm，不重复叠加。

F／B 的程序目标为编码器计数，L／R 为 0.01°。使用 A／B／C 的有符号计数中位数控制直线，四轮都记录；转弯使用每步新鲜 IMU 的相对变化，处理跨 360°。

各步连续运动、预测滑行停车，不做末端点动。原端点误差接受、IMU、堵转、航向、超时保护保留，超过容差则停止，不能把保护停机当合格入库。顺时针行驶时内部车库在车身右侧；初始左转是经现场验证的调位动作，不因换边就盲目镜像 L／R。

## 接线

不改现有引脚，STBY 仍为 PB15。

| 功能 | 接法 |
| --- | --- |
| 四电机方向／PWM | PD0～PD7／PE9、PE11、PE13、PE14 |
| 四路编码器 | 左前 PB6／PB7，左后 PA6／PA7，右后 PC6／PC7，右前 PA0／PA1 |
| 灰度 AD0／AD1／AD2／OUT | PB12／PB13／PB14／PC1 |
| IMU UART4 | PC10 TX→R，PC11 RX←T |
| 视觉 USART6 | PG14 TX→K230 GPIO6 RX（物理 Pin13）；PG9 RX←GPIO5 TX（物理 Pin11）；公共 GND（Pin14） |
| DAP USART1 | PA9 TX→DAP RXD，PA10 RX←DAP TXD，共地 |
| 云台 | PA2 上轴 180°，PA3 下轴 270°；电源沿用 5VDJ 稳压支路 |
| KEY／LED | PA15／PC13 |

两个 UART 都为 115200、8N1、3.3 V TTL。PC1 不耐 5 V，保留已确认的灰度电平保护；舵机不由 GPIO 或 3V3 供电。此独立固件没有合并 OLED 菜单。

## 测试和编译

[compile.ps1](compile.ps1) 只做测试和编译，不访问 COM、DAP 或电机：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\compile.ps1
```

需要完整仓库的 Core、Drivers、链接脚本及 10.12 build_pb15.mk；可通过 MakePath／ZigPath 指定工具。固件在 `固件/`，SHA-256 在 `SHA256SUMS.txt`。

四个实际 C 测试程序均通过：

1. 导航：8 种车位类型排列×3 个目标边，共 24 条模拟路线；覆盖不同第一／第二条线位置、非目标干扰、逐边数量、错窗、短丢线和非法计划停车。
2. 动作：六个分支的全部 3／5 步调度、端点及容差边界、角度跨圈、错边／错序列、KEY／IMU／堵转／超时停车。
3. 视觉调度：六种 RESULT、先定位再 SET4、200 ms 预检查、完整帧启动、重复／取消／过期／错误／会话变化不重复行车。
4. PWM：实际云台驱动的 PA2／PA3、50 Hz、两种行程、上电零占空比和定位等待。

输入与硬件在主机测试中为桩，24 条模拟路线不是 24 次实车成功。下一步应先恢复视觉板有效握手，再逐项实车测试六张卡；重点新增验证黄圆 BC 侧停、红三角 CD 倒库。此前第三题的 HELLO_TIMEOUT 尚未由本次离线编译解决，本轮没有读取或改动硬件状态。
