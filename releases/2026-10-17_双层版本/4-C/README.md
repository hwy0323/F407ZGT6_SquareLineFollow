# 双层版 4-C：BC 库内出发，到 C 停车

2026-10-17，用户现场确认到 C 位置正确：“没问题，挺好的”。按用户要求，将出库最后的前进 20 cm 与额外前进 5 cm 合并为连续前进 25 cm，命名为 4-C。不启用视觉，不转 C 弯，不继续前往 D／A。

## 路线与启动

BC 倒车车库内，车头朝外、八路循迹全亮：

1. 前进 10 cm。
2. 原地右转 50°。
3. 前进 18 cm。
4. 原地右转 60°。
5. 连续前进 25 cm，到 C 停车。

上电或复位保持停机，短按并松开 PA15 KEY，或通过 COM14、115200、8N1 发送字符 G 启动。KEY／串口 X 可停止。启动时检查全黑 FF 与有效 IMU 数据。READY 标识为 `DOUBLE_LAYER_4C_MERGED`，正常路线结束事件为 `C_REACHED_FROM_BC_GARAGE,turns=0`。

接线沿用[双层版统一接线](../接线.md)：STBY 为 PB15，灰度 AD0／AD1／AD2 为 PB12／PB13／PB14、OUT 为 PC1，IMU 使用 UART4 PC10／PC11。PC1 不耐受 5 V，制作 PCB 时须核对 OUT 电平并保护。

## 合并方式

前四步及转向控制保持原样；末段移除 20 cm 与 5 cm 之间的停车和再次起步，统一为 F250，目标 1433 个编码器计数，按 5.73 计数/mm 换算。

合并末段沿用原最后 5 cm 的有符号 A／B／C 编码器中位数、IMU 航向保持、连续 PWM、减速与 110 ms 滑行提前模型，不做末端点动。控制代码见 `c_final_forward.inc`。±20 计数为 DONE，±40 计数为 DONE_OFFSET，超出则 END_ERROR；IMU 失效、超时、堵转、反向或超程保护保留。前四步沿用旧控制器对 OVERSHOOT／DISTANCE_OVERSHOOT 的处理，不把其结果当作精度保证。

合并会改变停车起步与滑行过程，不等同于简单拼接两段实测位移；本目录保留两种固件，避免混用。

## 成功记录与原样备份

`已实测六步基线/` 保存现场认可的原六步源码、BIN／ELF 和完整串口、烧录日志。该次路线为 F100→R50→F180→R60→F200→停稳 500 ms→F50，5703 ms 报 C 到点，电机停止，没有继续转轨道弯。最后 F50 目标 287、实际结束 296 计数，约 5.17 cm；用户确认位置正确。

原六步的三段前进标为 DISTANCE_OVERSHOOT，两次转向约 50.70°／64.72°，后一转向标为 OVERSHOOT。原始偏差与事件保留在日志中，不能只看 C 到点事件判断精度。主目录 `固件/` 是用户要求的五步合并版；基线 `固件/` 是刚才现场认可的六步原版。

## 编译与文件

在本目录执行 `make all`，使用上级 `build.mk` 和仓库根目录 Core、Drivers、链接脚本，不依赖 experiments 目录。输出在 build，归档 BIN／ELF 在 `固件/`。

ARM 编译链接通过，保留继承的未使用函数和 nosys 桩警告。主机测试 `tests/test_C.c` 直接测试路线完成分支和末段控制器，覆盖五步表、1433 计数、无末端点动、终点偏差边界、KEY／IMU／超时／堵转／反向／超程及到 C 后不再循迹，测试通过。
