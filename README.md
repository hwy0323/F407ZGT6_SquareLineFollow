# F407ZGT6 智能小车分阶段测试工程

这是 STM32F407ZGT6 小车的分阶段测试工程。Git 历史中保留了正方形巡线、停车、编码器、激光测距和视觉联调等版本；当前提交用于 F407 直接驱动二自由度云台的上方舵机进行慢速往复测试。

## 当前测试版本：F407 直接驱动云台上方舵机

当前没有 C06B 云台控制板，F407 改用 `PA2 / TIM5_CH3` 直接输出 50 Hz 舵机 PWM。上方轴从中位 `90°` 开始，在 `60°～120°` 之间缓慢往复，每 `100 ms` 改变 `1°`，单程约 6 秒。下方轴不接线、不控制。

| 上方舵机线 | 接法 |
| --- | --- |
| 黄线（PWM 信号） | F407 `PA2` |
| 红线（电源正极） | D24A 四路驱动板标注的 `5V` 输出 |
| 黑线（电源负极） | D24A 四路驱动板 `GND` |
| F407 `GND` | D24A 四路驱动板 `GND`，必须共地 |

下方舵机的白、红、黑三根线全部不接并分别绝缘。舵机红线不能接 12 V，也不能由 F407 的 3.3 V 引脚供电。D24A 原理图中的 5 V 来自板载降压电路，但原理图没有标注连续输出电流；首次测试应让云台空载并确认舵机不卡死、5 V 稳定且降压芯片不过热。如果舵机抖动、复位或电源明显发热，应立即断电并换独立 5 V 大电流降压模块。

测试期间 TB6612 的 `STBY`（PC0）始终为低，四个车轮不会启动。当前版本只编译，不烧录。

## 历史版本：视觉识别结果显示

当前固件不会启动电机，TB6612 的 `STBY` 保持低电平。F407 使用 USART1 与 MaixCAM-Pro 通信，严格检查 `MV/1` 帧、XOR8、会话号和事务序号，只接受合法罗马数字结果：

| 视觉结果 | OLED 显示 |
| --- | --- |
| `I` | `1` |
| `III` | `3` |
| `V` | `5` |
| `VII` | `7` |

上电后屏幕立即全屏显示 `WAITING`，既用于检查 OLED 是否正常，也表示正在等待视觉板握手或第一次识别结果。识别成功后，屏幕保留最近一次数字，同时自动发起下一轮任务 3，持续识别。`FAIL` 表示识别超时或视觉侧返回失败，`ERR` 表示事务序号无法继续。

| 模块端 | F407 端 | 说明 |
| --- | --- | --- |
| MaixCAM A16 / TX | PA10 / USART1_RX | 视觉发送到 F407 |
| MaixCAM A17 / RX | PA9 / USART1_TX | F407 发送到视觉 |
| MaixCAM GND | F407 GND | 必须共地 |
| OLED SCL | PB8 / I2C1_SCL | SSD1306 |
| OLED SDA | PB9 / I2C1_SDA | SSD1306 |
| OLED VCC | 3.3V | 不接 5V |
| OLED GND | GND | 与两块板共地 |

MaixCAM-Pro 必须由自身 Type-C 供电。两块板之间只连接 TX、RX、GND；不要用 F407 的 3.3V 给视觉板供电。USART1 为 `115200 8N1`、3.3V TTL。若 ST-Link 或 USB-TTL 的串口线也接在 PA9/PA10，应先断开其 TX/RX，避免两个发送端互相驱动。

视觉侧必须运行已经接入新版 `roman_gray_template_cv_v1_single.py` 且会通过 A16/A17 发送 `MV/1` 帧的常驻程序。仅运行原始独立识别脚本时，结果只会打印到 MaixVision，F407 无法收到。

## 历史版本：纯编码器固定车位停车

当前工程的 T1、T2、T3 均使用固定 1 m 地图和编码器里程，不读取灰度模块。详细动作和调参方法见 [ODOMETRY_TEST_PLAN.md](ODOMETRY_TEST_PLAN.md)。上一版已验证的循迹停车方案仍保存在 GitHub 的前一个提交中。

右前编码器仍无有效计数，因此停车控制只使用左前、左后、右后三路。左侧距离取两个左轮平均值，右侧距离取右后轮；任一步骤编码器停止变化或运行超时，程序都会立即停车。

## 已验证功能：VL53L0X 激光测距

激光测距固件已经完成独立测试，但当前停车版本不会初始化激光模块。测试时使用的接线如下。

| 激光模块 ATK-MS53L0 | F407 引脚 |
| --- | --- |
| VCC | 3.3V |
| GND | GND |
| SCL | PA8（I2C3_SCL） |
| SDA | PC9（I2C3_SDA） |
| XSH | PC8 |
| INT | 不接 |

模块经 I2C 地址 `0x29` 访问，程序先验证型号 `0xEEAA`，再持续测距。ST-Link 可读取下列全局变量：`laser_distance_mm`（毫米）、`laser_sample_count`（样本数）、`laser_status`（`4` 表示正常运行）和 `laser_range_status`（`0` 表示有效距离）。本次实测距离从 71 mm 变为 50 mm，样本数从 56 增至 631，测距已验证可用。

灰度模块是 CD4051 八选一复用模块，并非八根独立输出线。本直连测试版用 3 根地址线和 1 根数字输入线，按顺序读取 8 个探头。

## 六任务菜单与 OLED

PA15 现在用于控制六任务菜单：

| 操作 | 行为 |
| --- | --- |
| 短按（少于 1 秒） | 选择下一项，任务 6 后回到任务 1 |
| 长按 3 秒 | 启动当前选中任务 |
| 任务运行中按键 | 立即停车 |

任务 1 是“正方形巡线”，任务 2 是“侧方停车模拟”，任务 3 是“倒车入库”，任务 4 是“四轮电机与编码器自检”。任务 5、任务 6 是安全占位项，确认后不会驱动电机。

OLED 未接入前，板载 PC13 LED 会按当前任务编号闪烁：例如两闪代表任务 2。未来接入 OLED 时，显示代码只需读取 `Core/Inc/menu.h` 中的 `Menu_GetSelectedTask()` 和 `Menu_GetSelectedLabel()`，无需修改电机、循迹或停车逻辑。

本工程现已支持常见的 128×64、4 针 I²C SSD1306 OLED：`VCC → 3.3V`、`GND → GND`、`SCL → PB8`、`SDA → PB9`。启动时会自动尝试地址 `0x3C` 和 `0x3D`。

屏幕单页大字显示当前任务：上电为 `T1`，每次短按依次切换 `T2` 至 `T6`，再回到 `T1`。长按确认后显示 `START`；任务结束或手动停止后自动回到 `T1`。若 OLED 未接好或型号不兼容，程序会跳过显示初始化，车辆菜单和安全停车功能仍可工作。

| 左前电机 A 方向 | PD0、PD1 | J4：AIN1、AIN2 |
| 右前电机 B 方向 | PD2、PD3 | J4：BIN1、BIN2 |
| 左后电机 C 方向 | PD4、PD5 | J6：CIN1、CIN2 |

| 启动 / 停止按键 | PA15 | 板载 KEY，低电平有效 |

### GT50 编码器

侧方停车和倒车入库使用四组霍尔编码器，四个电机仍按左右两组同步驱动。停车距离取四轮平均计数，左右纠偏取各侧前后轮平均计数。GT50 的六针线直接插 D24A 的电机接口，编码器由驱动板供电；只需把驱动板的 E1/E2/E3/E4 信号接入 F407。

| 编码器 | A 相 | B 相 | 定时器 |
| --- | --- | --- | --- |
| 左前 GT50（E1） | PB6 | PB7 | TIM4 编码器模式 |
| 右前 GT50（E2） | PA6 | PA7 | TIM3 编码器模式（当前信号无效，停车控制忽略） |
| 左后 GT50（E3） | PC6 | PC7 | TIM8 编码器模式 |
| 右后 GT50（E4） | PA0 | PA1 | TIM2 编码器模式 |

电机直插对应关系：左前 `MOTORC2`、右前 `MOTORC1`、左后 `MOTORC3`、右后 `MOTORC4`。E1A/E1B 位于 D24A 的 J4-10/J4-12，E2A/E2B 位于 J4-9/J4-11；E3A/E3B 位于 J6-10/J6-12，E4A/E4B 位于 J6-9/J6-11。J6-2 必须与 F407 GND 共地。

### 八路灰度模块

模块由稳定的 5 V 供电，模块 GND、F407 GND 和 TB6612 逻辑地必须共地。模块 5 V 不能接到电机 12 V 端，也不能改接 F407 的 3.3 V。

| 模块端 | 中间电路 | F407 端 | 信号方向 |
| --- | --- | --- | --- |
| 5V | 稳定 5 V 电源 | 非 GPIO | 供电 |
| GND | 直接共地 | GND | 参考地 |
| AD0 | 直接连接 | PB0 | F407 → 模块 |
| AD1 | 直接连接 | PB1 | F407 → 模块 |
| AD2 | 直接连接 | PB2 | F407 → 模块 |
| OUT | 直接连接 | PB10 | 模块 → F407 |

这是没有电平转换器时的临时直连方案。商家 STM32 参考例程也把 3.3 V GPIO 直接接到 AD0、AD1、AD2；若出现通道跳变、读数始终不变或不稳定，必须补 74HCT125 / 74AHCT125 地址缓冲，不能用软件掩盖。

模块由 5 V 供电，手册没有给出 OUT 的高电平电压。直接接 PB10 前，先确认 PB10 只作数字输入，并在首次上电后用万用表测量模块 OUT 的高电平。以后补齐硬件时，应改为 NPN 反相与 3.3 V 上拉级，避免把未知的 5 V 信号直接送进 MCU。

模块 EN 已在板内经 10 kΩ 下拉，不需要也不能额外连接 GPIO。PA13、PA14 保留给 SWD，PA15 保留给板载按键。

模块通道的地址关系如下。一次扫描返回的位图中，`bit0=CH1`，…，`bit7=CH8`。

| 软件索引 | AD2 | AD1 | AD0 | 模块通道 | 位图位 |
| ---: | ---: | ---: | ---: | --- | --- |
| 0 | 0 | 0 | 0 | CH1 | bit0 |
| 1 | 0 | 0 | 1 | CH2 | bit1 |
| 2 | 0 | 1 | 0 | CH3 | bit2 |
| 3 | 0 | 1 | 1 | CH4 | bit3 |
| 4 | 1 | 0 | 0 | CH5 | bit4 |
| 5 | 1 | 0 | 1 | CH6 | bit5 |
| 6 | 1 | 1 | 0 | CH7 | bit6 |
| 7 | 1 | 1 | 1 | CH8 | bit7 |

## 程序行为

程序用 PB0、PB1、PB2 选择通道，等待 50 µs 后由 PB10 读取该通道；8 路扫描约需 400 µs。微秒延时使用 F407 的 DWT 周期计数器，不会对每个探头执行 `HAL_Delay(1)`。

`main.c` 中的 `BLACK_LINE_LEVEL` 表示 MCU 侧“压到循迹线”的电平。此车实际赛道上探头灯亮，因此直连测试版设为 `GPIO_PIN_SET`。这来自实车观察，若更换赛道必须重新标定。

先断开电机使能，只检查传感器：

1. 模块探头距赛道约 18 mm。
2. 分别让每个探头处于背景和黑线，记录 PB10 扫描出的稳定位图。
3. 将压线时的 MCU 侧电平确定为 `BLACK_LINE_LEVEL`；若为低，改成 `GPIO_PIN_RESET` 后重新编译。
4. 用一条黑线从车头左侧扫到右侧，确认 CH1～CH8 对应真实左右顺序。若车转向相反，先核对探头的实际安装方向，再调整位图顺序或权重，不能同时盲改两处。

循迹使用权重 `{-7,-5,-3,-1,+1,+3,+5,+7}` 做比例纠偏。线偏左时左轮减速、右轮加速；线偏右时相反。中间两路中只亮一路属于轻微偏线，会按权重做小差速调整，不应停车。直角时连续识别到一侧 4 个探头压线，程序先低速前进 100 ms，再原地转向；中心探头重新压线后低速直行 100 ms，回到普通循迹。普通巡线默认完成第 4 个直角后停车；将 `LAP_TURN_LIMIT` 设为 `0U` 可持续绕圈。

初始低速参数为直线 `220 / 1000`、直角前进 `180 / 1000`、原地转向 `220 / 1000`。传感器全失、大片黑区或转弯超时会立即停止四路电机并拉低 STBY。

## 侧方停车（T2）

上电默认显示 T1。短按一次切到 T2，长按 PA15 3 秒启动侧方停车。当前是无车位的模拟版本：启动后不依赖视觉或灰度线，先低速直行一小段距离，再按编码器计数完成“倒车转入 → 倒车回正 → 前进微调 → 停车”。

模拟车位默认在行驶方向右侧。`main.c` 顶部的 `PARK_STRAIGHT_AHEAD_COUNTS` 是启动后的直行距离，其他 `PARK_*_COUNTS` 控制转入、回正和微调距离；它们均是按 GT50 标称编码器和约 65 mm 轮径给出的初始值，必须先完成低速定距测试，再按实测距离调整。未接编码器、计数不变化或单步超时，程序会在约 300 ms 后停机并拉低 STBY。

当前烧录的是侧方停车专用测试固件：不使用视觉和灰度模块，短按一次 PA15 即启动该模拟动作。停车距离暂时只取左前、左后、右后三路编码器平均值，忽略没有有效信号的右前编码器。再次按 PA15 会立即停车。

按键运行中再次按下 PA15，会立即停车。侧方停车的初次测试必须架空或在宽阔区域低速进行，确认两路编码器均有计数后再进入纸质车位。

## 倒车入库（T3）

短按两次切到 T3，长按 PA15 3 秒启动倒车入库演示。当前不启用视觉接口，也不读取灰度线：小车先低速直行一小段，再低速直线倒车，按左右前轮平均编码器计数停车。左右计数不同时，程序自动降低走得更远一侧的反向 PWM，以减少偏航。

`REVERSE_PARK_APPROACH_COUNTS` 是起步直行距离，`REVERSE_PARK_BACK_IN_COUNTS` 是倒车深度。初始值仅供架空低速测试；实际进入 35 cm × 30 cm 车位前，必须按轮径、轮距和实测编码器计数重新标定。编码器停滞、单步超时或按下 PA15 时均会立即停车并回到 T1。

## 四轮电机与编码器自检（T4）

T4 使用 USART1，通过 USB-TTL 以 `115200, 8N1` 通信。短按 PA15 三次选择 T4，长按 3 秒进入。进入后车辆保持停止，每 200 ms 输出 `LF`、`RF`、`LR`、`RR` 四轮编码器计数和四轮平均值；按 PA15 可随时停止并回到 T1。

串口单字符命令：`1`、`2`、`3`、`4` 分别低速正转左前、右前、左后、右后；`A`、`B`、`C`、`D` 分别低速反转左前、右前、左后、右后；`f` 四轮低速前进；`b` 四轮低速后退；`s` 停止；`r` 编码器清零；`p` 立即打印一组计数；`q` 退出 T4。首次测试必须架空四轮，确认每个命令只驱动对应车轮且对应计数持续变化后，才允许落地测试。

## 离线 Flash 路线记录器

当前的记录器版本不驱动电机：主循环始终使 TB6612 的 `STBY` 为低，四路 PWM 为零。它只读取左前、左后、右后三路霍尔编码器，并把路线写入 F407 Flash 扇区 11（`0x080E0000`）；该区域和程序区分开，断电后记录仍保留。

记录时不需要连接 ST-Link、USB-TTL 或电脑，但 F407 与霍尔编码器必须正常供电。手推小车时让四个轮子在地面正常滚动，不要架空单独转轮。

本次烧录的是第 3 次记录固件，只记录 DA 边侧方停车路线；没有任务切换或选择菜单。所有交互只用短按 PA15：

1. 上电后，LED 闪烁 3 次，表示 DA 侧方停车记录器已待命。
2. 从 A 点开始，按下文的 11 个关键点依次短按；第一次会自动清零编码器，LED 随后常亮。
3. 第 11 次按键后，LED 快闪 5 次，表示路线已安全写入 Flash。记录完成后保持停止，等待断电。

正方形数据确认无误后，我会分别生成第 2 次的 BC 倒车入库记录固件和第 3 次的 DA 侧方停车记录固件。三个槽相互独立，重新记录其中一条路线时，另外两条路线会保留。记录完成后重新接回 ST-Link，我可直接读取 Flash 扇区 11 并解码三路编码器的每个关键点，无需重新烧录或改动记录内容。

## 当前：BC 倒车入库模拟

当前固件不使用视觉模块，也没有菜单。短按一次 PA15 后，小车从 A 点低速循迹，经 B 点第一个直角弯进入 BC 边。灰度模块持续用于循迹；到达第 2 条 Flash 记录中的 BC 预停距离后，程序停止循迹，按记录的两段编码器里程执行低速前进弧线和低速小角度倒车，最后停车。

程序只读取 Flash 第 2 条记录，不会擦除三条已保存路线。若记录不存在、格式错误或三段里程为零，短按按键后电机保持停止。运行时再次按下 PA15 会立即停车。首次测试应架空车轮，确认 B 点转弯方向与后续弧线方向正确后，再在赛道与车位上低速测试。

当前测试版屏蔽了物理上从右数第二个探头（软件 `CH7 / bit6`），因为该通道故障常亮。其余 7 路仍参与循迹和直角判断；更换灰度模块后，应删除 `SENSOR_FAULTY_MASK` 的屏蔽代码并重新标定。

屏蔽 CH7 后，右半区只剩 3 路有效探头；直角识别已相应改为“右侧 3 路全亮”即判定右转，避免沿用原本“右侧 4 路全亮”的条件导致无法转弯。
